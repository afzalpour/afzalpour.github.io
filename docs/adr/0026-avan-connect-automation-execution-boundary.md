# ADR-0026 — مرز اجرای اتصال و اتوماسیون آوان

- Status: Accepted
- Date: 2026-09-13
- Related: ADR-0003, ADR-0005, ADR-0015, ADR-0016, ADR-0021, ADR-0022, ADR-0023, ADR-0025

## Context

ماژول ۹ باید امکان اتصال آوان به بانک، پایانه فروش، فروشگاه، فایل و سرویس‌های بیرونی را فراهم کند، اما اتصال بیرونی می‌تواند باعث اجرای تکراری، نشت اطلاعات حساس، ثبت مالی ناخواسته یا از بین رفتن قابلیت حسابرسی شود.

## Decision

1. هر Connector یک شناسه پایدار، Capabilityهای صریح و وضعیت واقعی دارد. قابلیت متصل‌نشده نباید فعال یا آماده وانمود شود.
2. مسیر اجرای واقعی Integration باید در محدوده Workspace، قابل حسابرسی و idempotent باشد.
3. کلید جلوگیری از اجرای تکراری در مرز امن سمت سرور ساخته می‌شود و حداقل Workspace، Connector، مرجع منبع و Hash محتوای ورودی را پوشش می‌دهد.
4. ثبت سند، پرداخت، ارسال بیرونی و سایر Mutationهای حساس پیش‌فرض Human-controlled هستند و بدون تأیید صریح اجرا نمی‌شوند.
5. اطلاعات حساس اتصال نباید در Browser runtime یا LocalStorage نگهداری شود.
6. هر اجرای واقعی باید Actor، Source Reference، وضعیت، زمان و نتیجه قابل ردیابی داشته باشد و مقدار حساس در Log/Audit ثبت نشود.
7. Marketplace می‌تواند Connector یا Workflow آینده را نمایش دهد، اما وضعیت آن باید صریحاً «متصل‌نشده» یا معادل فارسی روشن باشد تا زمانی که قرارداد واقعی آن فعال شود.
8. Foundation اولیه Module 9 فقط Registry، Marketplace و Dry-run/Preview ارائه می‌کند و هیچ Integration write path جدیدی فعال نمی‌کند.

## Existing capabilities reused

- ورود CSV صورت‌حساب بانکی و تطبیق کنترل‌شده.
- استخراج سند هوشمند با Edge Function احراز هویت‌شده و بازبینی انسانی.
- پیش‌اعتبارسنجی صورتحساب الکترونیکی با Adapter بی‌طرف نسبت به ارائه‌دهنده؛ ارسال واقعی همچنان غیرفعال است.

## Gate

- هیچ اتصال ساختگی به‌عنوان فعال نمایش داده نشود.
- Preview هیچ درخواست بیرونی یا Mutation مالی اجرا نکند.
- قرارداد idempotency و audit در Regression قفل شود.
- ADR-0025 برای تمام متن‌های قابل مشاهده کاربر رعایت شود.
- Company boundary حفظ شود.
- Production promotion فقط با مجوز صریح جداگانه انجام شود.
