# ADR-0025 — قرارداد فارسی روان برای تمام متن‌های قابل مشاهده کاربر

- وضعیت: **Accepted**
- تاریخ: **2026-09-13**

## زمینه / مسئله

آوان یک محصول فارسی‌اول برای کاربران ایرانی است. در چند سطح رابط، واژه‌های فنی یا مقادیر کُدی انگلیسی مانند `Snapshot`، `Foundation`، `Source of Truth` و enumهای دیتابیس می‌توانستند مستقیماً به کاربر نمایش داده شوند. این موضوع خوانایی، یکپارچگی تجربه کاربری و اعتماد حرفه‌ای محصول را کاهش می‌دهد.

## تصمیم

از این پس متن قابل مشاهده کاربر باید فارسی روان و متناسب با زبان حسابداری/مالی ایران باشد.

1. متن‌های ثابت رابط کاربر نباید واژه فنی انگلیسی غیرضروری داشته باشند.
2. مقادیر سیستمی و کُدی که از دیتابیس می‌آیند، مانند وضعیت‌ها، نوع برخورد مالیاتی و حالت‌های داخلی، در مرز نمایش به فارسی تبدیل می‌شوند.
3. مقدار اصلی و کانونی دیتابیس برای حسابرسی، منطق برنامه و سازگاری API بدون دلیل تغییر داده نمی‌شود؛ فارسی‌سازی در Presentation Boundary انجام می‌شود.
4. اگر یک مقدار سیستمی ناشناخته حاوی متن لاتین باشد، رابط نباید آن را خام نمایش دهد؛ باید از برچسب فارسی متناسب با همان زمینه استفاده کند تا نگاشت رسمی آن افزوده شود.
5. شناسه‌ها، URLها، کدهای قانونی/فنی و داده‌ای که کاربر عمداً با حروف لاتین وارد کرده است «متن رابط» محسوب نمی‌شوند و فقط وقتی برای فهم یا ردیابی لازم باشند نمایش داده می‌شوند.
6. هر ماژول جدید باید Regression داشته باشد که از بازگشت متن انگلیسی غیرضروری به UI جلوگیری کند.

## پیامدها

- تجربه کاربر در تمام ماژول‌ها فارسی و یکدست می‌ماند.
- داده مرجع و enumهای داخلی بدون مهاجرت غیرضروری حفظ می‌شوند.
- ترجمه و واژه‌گزینی در یک مرز مشخص قابل تست و توسعه است.
- نمایش مقادیر جدید دیتابیس نیازمند نگاشت فارسی یا fallback فارسی است.

## Guardrails / Invariants

- ترجمه نباید معنای حسابداری، حقوقی یا مالیاتی را تغییر دهد.
- داده اصلی دیتابیس صرفاً برای فارسی‌شدن UI بازنویسی نمی‌شود.
- ترجمه خودکار نباید جایگزین متن حقوقی/قانونی منبع شود؛ عنوان و مرجع قانونی باید با همان معنای معتبر، به فارسی قابل فهم نمایش داده شود.
- هیچ UUID خام یا enum انگلیسی نباید به‌عنوان برچسب اصلی کاربر نمایش داده شود.
- اصطلاحات ضروری برند/استاندارد فقط در صورت نیاز واقعی و با توضیح فارسی مجازند.

## گزینه‌های ردشده

- نگهداری متن انگلیسی و اتکا به آشنایی کاربر با اصطلاحات فنی: رد شد.
- تبدیل مستقیم تمام مقادیر دیتابیس به فارسی: رد شد، چون قراردادهای API، تاریخچه و قابلیت حسابرسی را بی‌دلیل تغییر می‌دهد.
- ترجمه آزاد و بدون Regression در هر صفحه: رد شد، چون دوباره باعث ناهماهنگی می‌شود.
