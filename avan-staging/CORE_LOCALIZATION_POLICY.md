# قاعده هسته: رابط کاربری کاملاً فارسی

این قاعده برای تمام نسخه‌های آوان الزامی است.

## اصل ثابت
هر متن قابل مشاهده برای کاربر باید فارسی سلیس، روان و قابل فهم باشد؛ شامل:
- عنوان‌ها، برچسب‌ها، گزینه‌ها و وضعیت‌ها
- پیام‌های موفقیت، هشدار و خطا
- خطاهای PostgreSQL / Supabase / RPC / Auth
- نوع اسناد، منابع، طرف‌حساب‌ها و وضعیت‌های داخلی
- گزارش‌ها، جداول، چاپ و خروجی‌های قابل مشاهده

هیچ error code، نام constraint، stack trace، پیام فنی Backend یا enum انگلیسی نباید مستقیماً به کاربر نمایش داده شود.

## استثنا
واژگان استانداردی که ترجمه آن‌ها غیرطبیعی یا گمراه‌کننده است، مانند PDF، CSV، SKU و URL، می‌توانند به همان صورت استاندارد باقی بمانند.

## مرز خطا
- جزئیات فنی خطا فقط در Console / log توسعه‌دهنده مجاز است.
- UI باید خطا را از `src/ui/errors/error-messages-fa.js` عبور دهد.
- اگر خطایی mapping اختصاصی نداشت، UI باید یک پیام عمومی فارسی نمایش دهد و هرگز متن خام خطا را fallback نکند.

## قاعده توسعه
هر feature جدید که enum، status، source type یا error code جدید ایجاد می‌کند، باید در همان تغییر، ترجمه فارسی قابل مشاهده آن را نیز اضافه کند.
