# Gate RC1.2-C.4.3 — Receipt OCR + Safe Delete

## Scope
این Gate دو مورد مستقل را کنترل می‌کند:

1. بازیابی مبلغ و تاریخ از رسید واقعی مرجع.
2. حذف امن اسناد هوشمندی که هنوز به پیش‌نویس حسابداری یا Ledger متصل نشده‌اند.

## پیش‌نیاز حذف
قبل از تست دکمه «حذف»، فایل زیر باید یک‌بار در Supabase SQL Editor اجرا شود:

`avan-staging/RC1_2_C4_3_DOCUMENT_DELETE_PATCH.sql`

این Patch:
- RPC حذف کنترل‌شده می‌سازد.
- حذف سند Linked یا دارای accounting draft را در Database مسدود می‌کند.
- اجازه پاکسازی فایل Storage را فقط برای عضو فعال Workspace با نقش مجاز می‌دهد.

## C4.3-A — رسید مرجع

1. Hard Refresh.
2. تصویر رسید مرجع را با نوع «رسید» یا «رسید بانکی» آپلود کنید.
3. «استخراج هوشمند» را اجرا کنید.
4. پس از اتمام، «بازبینی» را باز کنید.

### انتظار برای نمونه مرجع
- مبلغ روی رسید: `1,000,000 ریال`
- مقدار canonical آوان در حالت تومان: `100,000 تومان`
- تاریخ: `1405/06/10`
- شماره پیگیری/مرجع: `145575619`
- شرح می‌تواند به صورت ساختاری مشابه زیر باشد:
  `رسید کارتخوان — ... — پیگیری/مرجع 145575619`

اگر مبلغ یا تاریخ خالی باشد، بخش OCR این Gate FAIL است.

## C4.3-B — حذف سند بدون اتصال

1. یک فایل آزمایشی اضافه آپلود کنید و آن را به هیچ پیش‌نویس حسابداری/Ledger متصل نکنید.
2. در ردیف سند باید دکمه «حذف» دیده شود.
3. حذف را بزنید؛ Modal تأیید باید باز شود.
4. «حذف قطعی» را بزنید.
5. ردیف باید حذف شود.
6. صفحه را Refresh کنید؛ سند نباید دوباره ظاهر شود.

## C4.3-C — حفاظت سند متصل

برای سندی که:
- `status = linked` است، یا
- `linked_journal_entry_id` دارد، یا
- `extracted_data.accounting_draft.entity_id` دارد،

حذف باید در Server مسدود بماند. UI نیز نباید مسیر حذف عملی در اختیار کاربر بگذارد.

## Safety regression
- اصل سند دیگر با OCR به سند قطعی تبدیل نمی‌شود.
- Human Review اجباری است.
- Ledger، Journal lifecycle و RLS مالی تغییر نکرده‌اند.
- Canonical Ledger همچنان integer Toman است.
